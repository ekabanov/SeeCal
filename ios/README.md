# SeeCal iOS

On-device calorie, macro, and ingredient estimation from a single food photo.
Inference runs entirely locally: Qwen3.5-4B (MLX, 4-bit) plus a LoRA adapter
fine-tuned on Nutrition5K (see `../ml/` for the training pipeline).

## Layout

| Path | What it is |
|------|------------|
| `SeeCal/` | SwiftPM package — the entire app: domain contracts, MLX inference, persistence, and all SwiftUI screens (`SeeCalApp` product). Has its own [README](SeeCal/README.md) covering the module APIs and the JSON output schema. |
| `App/` | Thin Xcode app wrapper, generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `App/project.yml`. Adds what a package cannot carry: Info.plist (camera/motion usage strings), the increased-memory entitlement, signing, and the bundled model weights. |

The wrapper's only sources are `App/Sources/SeeCalApp.swift` (a `@main` shell
that hosts the package's `ProductionRootView`) and
`App/Sources/ModelAssetResolver.swift` (locates weights: bundled → simulator
fallback paths → device Documents/Application Support for side-loading).

`App/SeeCal.xcodeproj`, `App/Info.plist`, and `App/SeeCal.entitlements` are
**not committed** — XcodeGen generates all three from `App/project.yml` (the
single source of truth). Regenerate any time with `scripts/build.sh` or
`cd ios/App && xcodegen generate` (install XcodeGen with
`brew install xcodegen`).

## Requirements

- Xcode 26+, iOS 17+ deployment target.
- Runtime: a physical device with enough memory for a 4B model —
  **iPhone 15 Pro or newer** recommended. The app carries the
  `com.apple.developer.kernel.increased-memory-limit` entitlement.
- The simulator can build and run the UI, but MLX inference needs real
  Apple-silicon Metal — treat simulator runs as UI development only.

## Dev loop

```bash
# Fast UI iteration: simulator build, no weights bundled
SEECAL_ALLOW_NO_WEIGHTS=1 scripts/build.sh

# Signed device build with weights
MODELS_DIR=/path/to/models scripts/build.sh --device

# Everything: ml pytest + swift test + iOS build check
scripts/test.sh
```

Package-only work (most changes) is faster without the wrapper:

```bash
cd ios/SeeCal
swift test -Xcxx -DFMT_CONSTEVAL=
```

## Weights bundling

Weights are never in git. The app bundles them at build time via the
"Bundle model weights" build phase (`App/copy_weights.sh`). The **base model**
comes from `$MODELS_DIR`; required layout:

```
$MODELS_DIR/
└── mlx-community/Qwen3.5-4B-MLX-4bit/   base model, ~2.3 GB   (ml/download_model.sh)
```

The **shipping LoRA adapter** is a build artifact of the `ml/` pipeline, so it
is sourced straight from the repo — `ml/adapters_v5_swift/` (output of
`ml/convert.sh adapters_v5`), no manual staging. `copy_weights.sh` names the
shipping adapter in one place (`SHIPPING_ADAPTER`); update it when the shipping
adapter changes. Dropping an adapter at `$MODELS_DIR/adapters/` is an optional
override that takes precedence when present.

Without `MODELS_DIR` the build **fails with instructions**, unless
`SEECAL_ALLOW_NO_WEIGHTS=1` (simulator dev mode — on the simulator,
`ModelAssetResolver` falls back to local paths on your Mac; on device the app
also checks `Documents/` so weights can be side-loaded via Finder file
sharing).

## Release flow

One-time setup (stores App Store Connect credentials in repo-local
`.secrets/`, which is gitignored and verified so before anything is written):

```bash
scripts/release-setup.sh
```

You'll need an ASC API key (App Store Connect → Users and Access →
Integrations → App Store Connect API, "App Manager" access), your bundle id,
and your team id. Secret values are prompted without echo and never printed.
Re-run at any time to update values.

Then:

```bash
# TestFlight
MODELS_DIR=/path/to/models scripts/release-testflight.sh

# App Store (same upload; submit for review in App Store Connect afterwards)
MODELS_DIR=/path/to/models scripts/release-appstore.sh

# Rehearse without uploading: archive + export the signed .ipa, then stop
MODELS_DIR=/path/to/models scripts/release-testflight.sh --dry-run
```

Both scripts regenerate the project, archive Release for device, and upload
via `xcodebuild -exportArchive` with `method: app-store-connect` /
`destination: upload`, authenticated with the ASC API key
(`-authenticationKeyPath/-authenticationKeyID/-authenticationKeyIssuerID`).
The app record for your bundle id must exist in App Store Connect before the
first upload.

## Troubleshooting

- **`fmt` / `consteval` compile errors in mlx-swift**: Xcode 26's clang is
  stricter about `consteval` than the fmt vendored inside mlx-swift expects.
  Every script here passes `OTHER_CPLUSPLUSFLAGS='$(inherited)
  -DFMT_CONSTEVAL='` on the xcodebuild command line (a command-line override
  is required — project settings don't propagate into SwiftPM package
  targets). For package-only commands use `swift build/test -Xcxx
  -DFMT_CONSTEVAL=`. Building the app target from the Xcode GUI hits this
  error — build via `scripts/build.sh` instead.
- **App is killed loading the model on device**: confirm the build carries the
  `com.apple.developer.kernel.increased-memory-limit` entitlement (declared in
  `App/project.yml`) and you're on an iPhone 15 Pro or newer.
- **"MODELS_DIR is not set" build failure**: expected — see
  [Weights bundling](#weights-bundling).
- **"failed to determine current working directory" mid-build**: something
  regenerated `SeeCal.xcodeproj` (e.g. a concurrent `scripts/build.sh`) while
  a build was running. Don't run two builds/generations at once; rerun.
- **Release upload fails**: run with `--dry-run` first; the scripts print a
  specific remedy at each precondition (missing `.secrets/` → run
  `scripts/release-setup.sh`; signing failures → team/bundle-id/API-key access
  checklist; upload failures → missing app record or duplicate build number).
